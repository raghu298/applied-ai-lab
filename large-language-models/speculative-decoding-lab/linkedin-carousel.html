Field notes · 01@raghunath

The insight

Generating is slow. Checking is fast.

Producing one token forces a full read of the big model's weights while the compute units sit idle — decoding is memory-bound.

But verifying whether k tokens are what the model would've said costs just one forward pass. Same parallelism as reading a prompt.

So the plan

Let a cheap model guess ahead. Let the big model verify the whole guess at once.

target = load("gpt2")        # 124M

# draft guesses k; target verifies in ONE pass
guesses = draft_k(draft, ids, k=4)
logits  = target(ids + guesses)      # single call
keep    = longest_prefix_target_agrees(logits, guesses)
ids += keep + [correction(logits)]  # free token

Field notes · 05@raghunath

The elegant part

It's not an approximation. It's exact.

You might expect a shortcut like this to cost quality. It doesn't. A rejection-sampling rule — accept a guess with probability min(1, p/q), else resample from what's left — makes the output distribution mathematically identical to the big model sampling alone.

Why it matters

No quality knob to tune, no drift. That exactness is why vLLM, TGI and TensorRT-LLM all ship it by default.

Field notes · 06@raghunath

The honest caveats

AIt's a latency tool, not a throughput tool

At large batch sizes the GPU is already busy; verification competes with other users' work and can lower fleet throughput.

BPredictable text drafts best

Chat, code, and RAG that quotes its context hit high acceptance. Creative, high-temperature sampling drafts poorly.

CTune the guess length k

Too long wastes drafts on rejections; too short wastes the trick. Measure acceptance, then set k.

Field notes · 07@raghunath

What I took away

Free speed hiding in wasted bandwidth.

The GPU was idling between memory reads the whole time. Speculative decoding just fills that gap with guesses — and refuses to accept a single wrong one.
